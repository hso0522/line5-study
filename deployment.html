아래 과정은 본인 계정에서 진행하세요. 비밀번호·토큰·인증코드를 채팅에 보내지 마세요. Public 저장소와 웹앱은 누구나 볼 수 있으므로 PDF·사진 공개 권한을 먼저 확인하고 비공개 자료는 업로드하지 마세요.

01

GitHub 계정과 초기 설정

  1. github.com 접속 → 계정이 없으면 Sign up, 있으면 Sign in.
  2. 이메일·비밀번호·사용자명을 입력해 가입하고, 받은 이메일로 인증합니다.
  3. 사용자명(username)을 기록하세요. 표시 이름과 다르며 사이트 주소에 들어갑니다.
  4. 우측 프로필 → Settings → Password and authentication에서 2단계 인증/패스키 설정을 권장합니다. Pages용 API 토큰은 필요 없습니다.
02

웹앱 ZIP 다운로드·압축 해제

  1. 배포 ZIP 페이지에서 GitHub 배포 ZIP 다운로드 클릭.
  2. 다운로드한 line5-study-github.zip을 압축 해제합니다. Windows: 우클릭 → 모두 추출. macOS: 더블클릭.
  3. 압축 푼 폴더 안에 index.html, css/, js/ 등이 있는지 확인합니다.

ZIP 파일 자체가 아니라 압축을 푼 내용물을 업로드합니다.

03

저장소 생성하기

  1. 새 저장소 생성 또는 우측 상단 + → New repository.
  2. Owner: 본인 계정. Repository name: line5-study.
  3. Public 선택. 무료 계정에서 시작하기 가장 간단합니다.
  4. Add a README file 옵션을 켜고 Create repository 클릭. .gitignore·라이선스는 일단 비워도 됩니다.
  5. Code 탭의 브랜치가 main인지 확인합니다.

저장소(repository)는 사이트 파일을 보관하는 공간입니다. 이때 웹앱이 공개된 것은 아닙니다.

04

파일 넣기 · 가장 중요한 단계

  1. 저장소 Code → Add file → Upload files 클릭.
  2. PC 파일 탐색기에서 압축을 푼 폴더를 엽니다.
  3. 폴더 안의 파일과 css, js, images, materials 폴더를 선택해서 GitHub 업로드 영역으로 끌어 놓습니다. 바깥쪽 압축 해제 폴더 자체를 넣지 마세요.
  4. 목록에 css/style.css, js/app.js처럼 하위 경로가 유지되는지 확인합니다.
  5. 아래 Commit changes 메시지에 Add LINE 5 web app 입력 → Commit directly to main → Commit changes. 이 버튼을 눌러야 저장됩니다.
  6. Code 첫 화면에 index.html이 바로 보이는지 확인합니다. 기존 README는 ZIP의 최신 파일로 덮어써도 됩니다.

잘못된 예: ZIP만 올림 / line5-study-github/index.html로 한 단계 더 감쌈 / 폴더를 없애고 파일만 모음.

숨김 파일이 안 보이거나 폴더 업로드가 안 될 때

초보자용 브랜치 배포에는 .github/가 필요하지 않으므로 생략하세요. .nojekyll이 누락되면 Add file → Create new file → 파일명 .nojekyll → 내용에 Static site → Commit changes.

폴더 업로드가 막히면 GitHub Desktop → Clone repository → 압축 푼 내용물을 clone 폴더에 복사(.git은 유지) → Commit to main → Push origin을 사용하세요. 전체 문서에 상세 대안을 적었습니다.

05

GitHub Pages 켜기

  1. 저장소 상단 Settings 클릭. 프로필 Settings와 다릅니다.
  2. 왼쪽 Pages → Build and deployment.
  3. Source → Deploy from a branch 선택.
  4. Branch → main, 폴더는 /(root) → Save.
  5. Custom domain은 비워 둡니다. 도메인 구매는 필요 없습니다.
  6. 몇 분 기다린 뒤 Actions 탭의 pages build and deployment 실행에서 초록 체크를 확인합니다.
  7. Settings → Pages → Visit site에 표시된 주소로 접속합니다.
SourceDeploy from a branchBranchmainFolder/(root)

공개 주소 형식: https://사용자명.github.io/line5-study/

github.com/…은 코드 저장소, github.io/…가 웹앱 주소입니다. 위 주소는 예시이며 실제 주소는 Pages 화면에서 확인하세요.

06

공개 확인과 휴대폰 설치

  • 홈의 168문항 표시와 퀴즈 채점·오답·배지·PDF 링크를 확인하세요.
  • Android Chrome: 웹앱 주소 접속 → 메뉴의 앱 설치/홈 화면에 추가.
  • iPhone Safari: 공유 → 홈 화면에 추가 → 추가.
  • PC Chrome·Edge: 주소창 설치 아이콘 또는 설치 메뉴.

처음 HTTPS 주소에서 온라인으로 열어 앱 캐시가 완료된 뒤 오프라인 학습을 확인하세요. PDF는 온라인으로 열어본 뒤에만 캐시될 수 있습니다. 설치 메뉴는 브라우저마다 다릅니다.

미리보기 학습 기록이 GitHub 주소로 자동 이전되지 않습니다. 기록은 기기·브라우저별이며 다른 기기로 동기화되지 않습니다.

07

수정한 파일 다시 배포하기

  1. 새 ZIP을 압축 해제하고 같은 저장소에서 Add file → Upload files.
  2. 바뀐 파일을 같은 경로로 올립니다. 예: 문항은 js/questions-2016.js.
  3. Commit changes → Actions 초록 체크 → 실제 웹앱 확인.
  4. PWA 파일 변경 시 sw.js의 캐시 버전을 올립니다. 현재 line5-v0.6.0.
  5. 옛 화면이 보이면 앱·탭을 모두 닫고 다시 엽니다. PC 강력 새로고침: Ctrl+Shift+R / macOS Cmd+Shift+R.

업로드는 같은 파일을 덮어쓰지만 옛 파일을 자동 삭제하지 않습니다. 불필요한 파일은 저장소에서 해당 파일을 열어 삭제·commit합니다.

사이트 데이터 삭제는 학습 기록도 지웁니다. 먼저 배포 완료 여부와 앱 재시작을 확인하세요.

08

문제가 생기면 여기부터

사이트가 404이거나 README만 나와요

index.html이 최상위인지, main / (root) 설정인지, Actions 실행이 성공했는지 확인하세요. 코드 저장소 주소가 아니라 Pages가 제공한 github.io 주소를 사용합니다.

디자인·사진·문제가 안 보여요

css/, js/, js/vendor/, images/, materials/가 누락되지 않았는지 확인하세요. 파일명 대소문자는 정확히 맞추고 경로 앞에 /를 붙이지 마세요.

main이나 Pages 메뉴가 안 보여요

본인 소유 Public 저장소인지, 이메일을 인증했는지, 파일을 commit했는지 확인하세요. 실제 브랜치 이름이 main이 아닐 수도 있습니다.

Actions에 빨간 X가 나와요

실패한 실행 → job → 빨간 단계에서 로그를 확인합니다. 초보 브랜치 배포라면 .github/ 사용자 workflow를 생략하세요. Actions 방식은 Pages Source를 GitHub Actions로 선택해야 합니다. 전체 문서의 대안 B를 참고하세요.

준비가 되셨나요?

ZIP을 받고 01 → 05 순서대로 진행하세요. 아직 본인 계정의 배포 작업은 실행되지 않았습니다.
